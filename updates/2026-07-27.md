## WorldWeaver and Solaris multi-agent world-model lineage

The catalog now follows a complete public-to-unreleased data chain instead of
recording WorldWeaver as an isolated new paper:

- **WorldWeaver** is linked to a dedicated card for its approximately 126-hour
  synchronized two-agent Minecraft corpus. The paper documents 832x480 video at
  20 FPS, per-agent state and controller logs, a shared overhead camera, and
  Qwen2.5-VL-72B-Instruct scene text for every four-frame chunk. The card is
  deliberately marked unavailable because no files, download path, dataset
  license, code, or checkpoints have been published.
- **Solaris** is added as the open-weight upstream multiplayer world model. Its
  runnable four-stage pipeline links the public VPT contractor demonstrations,
  the public 12.64M-frame / 9,240-episode Solaris Training Dataset, and the
  public 1,280-row Solaris Eval Datasets. The inherited Matrix Game 2.0 corpus
  remains an unresolved reference rather than being guessed from the base
  checkpoint name.
- **Solaris Training Dataset** and **Solaris Eval Datasets** have direct Hugging
  Face download actions. Their official Apache-2.0 declarations are recorded,
  while Minecraft/Mojang media-rights review remains separate from repository
  licensing. **VPT Contractor Demonstrations** points to OpenAI's official MP4
  and JSONL indices and explicitly distinguishes that public release from the
  70,000-hour online-video corpus in the original VPT pipeline.
- WorldWeaver's evaluation edge resolves to the Solaris test release used by
  the paper, while its inherited single-player video prior remains unknown.
  Thus the detail view shows both navigable cards and unresolved evidence
  boundaries instead of turning every named input into a fake download.

Six new critical probes watch both model repositories and all four dataset

## ElasticTTT runtime data and evaluation lineage

ElasticTTT is now represented as three separate evidence layers so the strategy
view no longer makes a per-run input look like a missing downloadable corpus:

- **Inherited pretraining data:** the method reuses a Wan video diffusion
  backbone, but the ElasticTTT paper does not enumerate that base model's full
  source corpus or mixture. This remains an unresolved pretraining reference.
- **Runtime adaptation data:** each edit run optimizes a LoRA for 100 steps on
  one user-provided source video. This is now labeled `runtime-input`, not as an
  unpublished publisher dataset, and intentionally has no dataset card.
- **Public evaluation data:** the official Hugging Face release contains 25
  source MP4 files and five target edit instructions per video, yielding the
  paper's 125 text-video pairs. It is linked as an evaluation dataset rather
  than training supervision and has a direct access action in the site.

The evaluation card traces its 25 selected source videos to **DAVIS 2017**.
DAVIS now has a separate source card recording the official totals of 150
sequences, 10,459 annotated frames, and 376 objects, plus the direct official
480p/full-resolution download page. Both public cards retain a rights warning:
neither the ElasticTTT repository nor the DAVIS download page states a clear
commercial-use and redistribution license, so public access is not treated as
permission.

The model card also preserves an implementation boundary that would otherwise
be easy to miss: the paper reports a Wan2.1-1.3B setup, while the current
research-preview repository targets Wan2.2-TI2V-5B and says the final version
is still forthcoming. No standalone ElasticTTT weights are claimed.

The catalog now contains 101 datasets, 86 models, 116 explicit model-to-dataset
role relations, 27 dataset-lineage relations, and 281 watched first-party
sources. The accepted 281-source live scan completed with zero new candidates,
important revisions, source failures, recoveries, ranking changes, or ranking
coverage gaps.

## Cinematic dubbing and production lip-sync lineage

Three recent systems now expose their data strategy as navigable model ↔
dataset relations instead of leaving dataset names inside paper prose:

- **DiFlowDubber** pretrains a zero-shot TTS prior on a disclosed 470-hour
  LibriTTS subset, then adapts separate models on Chem and GRID. LibriTTS and
  GRID have official download surfaces; Chem does not. The official repository
  remains a paper/project shell and still marks implementation and checkpoints
  as coming soon.
- **FunCineForge** trains its main 0.5B cinematic-dubbing system on CineDub-CN,
  a 7.2 TB internal corpus distilled from more than 6,000 raw Chinese television
  hours into 1,559,172 samples and more than 4,700 effective speech hours. The
  code and bilingual checkpoint are public, but the full corpus is not. The
  separately released CineDub-Example repository is gated, non-commercial, and
  contains roughly 52.93 GB of Chinese and English examples; it is not presented
  as the complete training set. A controlled comparison links the model to
  V2C-Animation, Chem, and GRID for both training and evaluation roles.
- **UniSync** fine-tunes an undisclosed audio-image-to-video base model on a
  named but unreleased 5,000-video high-resolution corpus. It evaluates on HDTF
  and the new 495-video RealWorld-LipSync benchmark. The paper promises the new
  benchmark for future public release, but no files, repository, weights, or
  license are currently available.

The acquisition layer keeps four states separate: direct official downloads
(LibriTTS and GRID), reconstruction metadata without redistributable media
(V2C-Animation), gated examples (CineDub-Example), project/metadata-only
corpora (Chem and CineDub-CN), and paper-only unavailable corpora (UniSync 5K
and RealWorld-LipSync). Eleven new critical probes watch every added model and
dataset surface for repository, checkpoint, file, access, or license changes.

## Video Try-On data-strategy expansion

The Try-On track now includes two complementary 2026 systems and three data
cards that make the difference between a named corpus and a downloadable
release explicit.

- **OmniTryOn** starts from Video-As-Prompt / Wan2.1-I2V-14B and fine-tunes
  exclusively on TryAny-Bench. The public benchmark contains 1,460 paired
  reference/target videos (1,243 train and 217 test) retained from more than
  1,500 e-commerce videos. Its two Hugging Face archives are directly hosted,
  but the repository declares no license or dataset card, so access is not
  represented as permission.
- **iTryOn** uses a two-stage recipe: 10K steps on the public ViViD corpus,
  followed by 10K steps on VVT-Interact. VVT-Interact contains 5,292
  video-garment pairs across six interaction categories, with global captions
  and time-stamped action captions. The paper provides no files, request form,
  or release date, so its data card is deliberately marked unavailable rather
  than linking the paper as a download.
- **ViViD** now has its own acquisition card. The official repository hosts a
  roughly 32.1 GB archive covering 9,700 garment-video pairs and 1,213,694
  frames plus agnostic, mask, and DensePose conditions. The repository declares
  Apache-2.0, while the underlying Net-A-Porter media still requires a separate
  upstream-rights review.

Both model cards expose their stage-by-stage operations, inherited foundation
data unknowns, public/unreleased references, and canonical model ↔ dataset
links. Five new critical revision probes watch both model surfaces and all
three datasets.

## Dataset acquisition links

Every dataset card now has a visible acquisition action in the generated README,
the website's expanded dataset view, and the new
[`DATASET_ACCESS_INDEX.md`](../DATASET_ACCESS_INDEX.md). The action distinguishes:

- directly hosted files or a browsable repository;
- an official downloader or URL manifest;
- a gated application/request page;
- metadata/tooling only; and
- an official availability notice when no files are published.

This avoids labeling an account gate, URL-only corpus, or unavailable benchmark
as a direct download. OpenHumanVid now links straight to the
