## Dataset acquisition links

Every dataset card now has a visible acquisition action in the generated README,
the website's expanded dataset view, and the new
[`DATASET_ACCESS_INDEX.md`](../DATASET_ACCESS_INDEX.md). The action distinguishes:

- directly hosted files or a browsable repository;
- an official downloader or URL manifest;
- a gated application/request page;
- metadata/tooling only; and
- an official availability notice when no files are published.

This avoids labeling an account gate, URL-only corpus, or unavailable benchmark
as a direct download. OpenHumanVid now links straight to the
[official access form](https://forms.gle/moqec5Qod7mz9pfD6), while its project
page remains evidence rather than the primary acquisition action.

sites. These entries appear in [`SOURCE_PLATFORM_INDEX.md`](../SOURCE_PLATFORM_INDEX.md)

## Monitoring changes

The scheduled discovery baseline now covers:

- 182 watched sources, including all 16 source-platform access surfaces;
- 50 important datasets;
- 37 important models;
- ten ranking boards; and
- eight dataset-release feeds.

Important official HTML and PDF sources that do not expose a GitHub commit or
Hugging Face revision now receive a SHA-256 content revision. HTML fingerprints
use normalized visible text and metadata, excluding scripts, styles, hydration
payloads, and markup-only build changes. A changed hash creates a review signal;
it never edits factual cards automatically. Sources that require authentication,
such as the current Flickr repository, stay linked in their cards but are not
misreported as successful anonymous probes.

The stale Reve blog path and Kuaishou investor-news path were replaced with
their current official locations. GitHub API probes now use the workflow token,
and a connection reset is isolated as one source failure instead of aborting the
whole run. After accepting the reviewed 151-source baseline, two consecutive
live authenticated scans both ended with zero new candidates, zero important
revisions, zero source errors, and zero ranking changes. This specifically
proves that the six dynamic HTML false positives seen before canonicalization no
longer reproduce. The later Arena coverage pass adds seven model-specific
official probes; its refreshed 163-source baseline is verified separately below.

## Dataset monitor coverage expansion

Nineteen additional official probes close the revision-monitoring gap for
recent benchmarks, named model-training corpora, preference data, historical
video sources, audio datasets, and 3D assets. This includes GraphVid-Bench,
GenSyn10, ERIA-1K, Lens-800M, Lens-RL-8K, SoundAtlas, AudioCaps 2.0,
Re-LAION-5B, Pick-a-Pic v2, Objaverse-XL, JourneyDB, WebVid-10M, Clotho 2.1,
FSD50K, VGGSound, FMA, AudioSet, YFCC100M, and Million Song Dataset.

The catalog now independently monitors 50 of 51 dataset cards. Flickr 5B is
the sole explicit exception because the current Hugging Face metadata endpoint
requires authentication; retaining that exception is more accurate than
recording a permanently failing anonymous probe. All other datasets directly
linked from a model card now have a monitor. GitHub repositories use their
verified default branches, Hugging Face repositories use metadata revisions,
Zenodo records use the official API, and official publication/project pages use
normalized content hashes. Scheduled scan concurrency is reduced from eight to
four workers, and transient transport plus retryable HTTP failures receive
bounded backoff retries. This lowers connection-reset noise without narrowing
the source set or hiding persistent failures. Zenodo probes use their stable
record modification time and revision number instead of hashing unordered API
arrays. Baseline acceptance now fails closed if any source is unavailable,
unless a reviewer deliberately supplies the explicit failure override.

Hugging Face dataset-release candidates now carry a transparent review score
and high/standard/low priority. Signals include an explicit generative-media
match, image/video modality tags, linked paper, dataset-card metadata, declared
license/size, adoption, gating, and thin or archive-like metadata. The scanner
retains low-priority candidates so a genuinely new release is not hidden merely
because it has few downloads. The accepted baseline currently contains 142
release-feed candidates: 55 high, 48 standard, and 39 low.

The supplied website-planning sheet was re-read in full. Its 16 effective rows
match the 16 public source-platform profiles already present in the repository;
no site was missing. As before, internal operational assessments are not copied
into the public repository.

After accepting the authenticated 182-source snapshot, a second independent
authenticated scan reported zero new candidates, zero important revisions,
zero failures or recoveries, zero ranking changes, and zero ranking coverage
gaps. The stored baseline itself contains 182 sources and no source error.
